# 开发阶段与交付计划

更新日期：2026-09-17。状态：阶段划分为工作方案；没有承诺工期或完成日期。

## 执行顺序

先验证传感器能力，再修订可验收需求与冻结设计，然后实现数据链和界面。原讨论 M0～M5 保留；在正式功能编码前增加独立可行性验证步骤。采集原型是验证产物，不自动成为生产实现。

| 阶段 | 工作 | 交付物 | 退出条件 |
|---|---|---|---|
| M0 需求整理 | 合并有效讨论、术语、来源和未决事项 | 本文档集、需求 ID、风险清单 | 文档可追踪；不假称全部需求已冻结 |
| V0 传感器验证 | M4 Air 枚举、语义、权限、五档、生命周期 | 能力表、采样记录、验证报告 | 关键指标有证据；不可实现项明确 |
| M1 架构与详细设计 | 根据 V0 确定接口、指标、数据模型、算法、UI、故障和工具链 | 经评审的 13 类设计文档、验收标准 | 阻塞决策闭合，正式功能编码前完成评审 |
| M2 数据链 | 采样、标签、Ring Buffer、EMA、Raw 聚合、趋势、SQLite | 核心模块及集成测试 | 数据流、清理、故障路径通过对应测试 |
| M3 原生 UI | 菜单栏、面板、主窗口、图表、档位与查询 | 可交互原生 App | UI 黑盒及数据来源验收通过 |
| M4 系统集成 | 端到端、故障注入、生命周期、长期运行、多机型 | 系统测试与兼容矩阵 | 阻塞缺陷解决；资源预算达到定义门槛 |
| M5 Release Candidate | 全需求验收、签名公证、安装与运维检查 | RC 构建与最终报告 | 已声明平台通过；版本与已知限制明确 |

2026-09-15 用户授权最小验证，已开展 V0 的首轮原型与实机采样，见 [报告](validation/2026-09-15-m4-air/validation-report.md)。V0 退出条件尚未满足：Package／逐核语义、完整生命周期等仍待验证。未进入生产功能编码。

## 编码前文档集合

此前确定的 13 类文档在本目录均有对应文件：需求、总体架构、采集、数据模型、加工链、错误处理、原生 UI、详细构件、技术选型、测试、Git/GitHub、开发计划、运维诊断。

**有文件不等于设计已完成。** 本轮将未确定的类接口、阈值、机型能力、视觉规范和 schema 显式保留为待决策项。正式编码门禁取决于内容评审与阻塞事项闭合，而非文件数量。

## 每个功能的交付单位

功能需求与设计 → feature branch → 实现 → 相应测试 → 缺陷 Issue 与修复 → PR → 门禁通过 → merge commit → 保留分支。

建议首个功能切片是已验证 CPU 主指标的采集到加工和存储；不得为了推进该切片而默默删去用户要求的其他指标。后续每项指标可用性必须在兼容矩阵中说明。

## 计划尚缺的输入

参与者、可用于验证的 Air 机型和系统、工期、代码库位置之外的远端协作信息，以及阶段评审责任人尚未指定。无需为整理文档填入虚构负责人和日期。

## V0后续顺序（2026-09-17）

已完成 [7项参考项目复核与方案文档](19-reference-informed-design.md)。接下来按其V2-01～06推进：CPU/附件来源验证 → 身份和故障边界 → 同源集合缓存对比 → 最小数据链 → UI及发布构建。RC-01～04和OQ-04决定产品验收范围；文档完成不代表这些事项已关闭。

首个数据链切片使用一个已经验证的CPU指标；用模拟provider验证数学与存储后接真实来源。保持已有Raw/EMA与分级历史要求，不从参考项目引入风扇、功耗或网络等新功能。
