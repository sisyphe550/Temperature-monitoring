## 验证目标

首个建议对象是 M4 MacBook Air，固定一台机器及其实际 macOS 版本与 build。记录机型标识、芯片、尺寸、供电状态和构建配置；不将“当前设备”自动认定为该目标机器。

需要回答：哪些温度可读、数值的物理含义、普通用户权限是否足够、五档调度如何表现，以及睡眠唤醒后是否恢复。

## 原型形式

独立命令行目标，Swift 为主，必要时加入小型 C／Objective-C 桥接。功能仅包含枚举、读取、记录、计时和诊断输出。原型代码若要进入产品，需要重新整理接口、测试和许可，不直接将探索代码视为生产实现。

## 验证步骤

| 阶段 | 操作 | 证据与判定 |
|---|---|---|
| V-01 环境记录 | 确认机型、系统 build、用户权限及构建配置 | 可复现环境记录 |
| V-02 传感器枚举 | 分别检查 AppleSMC、HID、SSD SMART、IOPowerSources | provider、原始 ID、返回类型、单位、能力状态 |
| V-03 数值与语义 | 空闲、日常使用、短时 CPU 负载；参考 Stats／macmon 交叉检查 | 单位与异常值证据；确认与未确认映射分开 |
| V-04 五档计时 | CPU 每档先跑数分钟；SSD/Battery 按各自周期 | 实际间隔、读取耗时、调度延迟、漏采、错误、资源开销 |
| V-05 生命周期 | 睡眠唤醒、插拔电源、停止再启动、切换档位 | 恢复行为、数据缺口、连接与资源释放 |
| V-06 数据链 | Ring Buffer、EMA、Raw 聚合、SQLite 与查询，初步运行约一小时 | 样本流转、参数、清理、队列与数据库行为 |
| V-07 发布配置 | 候选签名／Hardened Runtime 配置下重复关键读取 | 与调试构建的能力差异 |

“每档数分钟”和“约一小时”是粗略验证安排，不是已经完成的测试或足以证明长期稳定的门槛。之后需安排覆盖 72 小时历史保留机制的长期测试。

## 记录指标

每次读取建议记录请求时间、开始／结束时间、实际读取值、原始 key、返回状态、源更新时间（若存在）、当前档位和重试次数。统计实际间隔与耗时的中位数、较高分位和最大值，以及有效率、漏采率、CPU、内存与队列大小。

统计口径先定义：漏采按目标调度机会还是已启动调用计数；错误是否含重试；同值重复不应被当成无效读取。阈值和通过标准见 OQ-02/OQ-10。

## 不能从测试推出的结论

- 其他软件读数一致不等于计量校准，也不能单独证明逐核映射。
- 传感器随 CPU 负载升温仅提供相关性证据。
- 调用每 50 ms 成功不证明硬件每 50 ms 更新。
- 相同值既可能是稳定温度，也可能来自缓存；没有更新时间信息时保留未知状态。
- 一台 M4 Air 通过不代表其他尺寸、代际或系统版本通过。
- 一个小时无异常不证明连续三天资源有界。

## 建议交付物

| 产物 | 内容 |
|---|---|
| `capabilities.json` | 机型、系统、provider、原始传感器、单位、能力、映射证据 |
| `sampling-results.csv` | 五档计时、读数与错误记录 |
| `validation-report.md` | 已证实／未证实／不支持项、方法、限制、下一步 |
| `compatibility-matrix.md` | 每个实测环境下的指标与档位结果 |

首轮已生成上述类型的真实证据，CSV 在仓库中以 gzip 无损压缩归档；原始文件 SHA-256 与复现方法随报告保存。未执行项仍显式标注。

## 决策出口

能力充分：冻结来源、指标命名、权限和采样验收语义。能力部分满足：明确差异并讨论调整范围或显示不可用。关键 CPU 指标无法取得：如实标为阻塞，重新决定路线，不能用模拟温度通过硬件验收。
