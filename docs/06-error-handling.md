# 故障分类、重试与错误码

更新日期：2026-09-14。状态：重试参数用户已接受；错误码为授权设计基线；传感器缺失的退出边界待决策。

## 原则与当前冲突

用户要求构件失败先重试，无法恢复后报告错误、保留日志并退出。v0.3 将结构性错误直接判为 Fatal。C03/C04 又提出“能力不支持”应与“运行中故障”区分，但用户尚未决定单项指标缺失是否允许应用继续。

因此本版保留原退出要求，不擅自将它改成自动降级。实现前必须解决 OQ-05：必需指标集合、可选指标集合和不支持／权限不足的用户行为。

## 重试参数

重试次数不含首次尝试。例如最多 3 次重试表示最多 4 次调用。

| 范围 | 最大重试次数 | 依次等待 | 纯等待合计 |
|---|---:|---|---:|
| 传感器暂时失败／无效读取 | 3 | 50、100、200 ms | 350 ms |
| SQLite 暂时性打开／读取／写入失败 | 5 | 100、250、500、1000、2000 ms | 3850 ms |
| 数据加工暂时执行失败 | 3 | 50、100、200 ms | 350 ms |
| UI 数据读取暂时失败 | 3 | 100、250、500 ms | 850 ms |

成功后立即结束本轮重试。总耗时还包括每次调用耗时；上表不是总超时上限。50 ms 档位下不能为每个定时触发叠加独立重试链。读取超时、调用取消能力、重叠任务处理、SQLite busy timeout 与应用重试的组合见 OQ-09/OQ-10。

不对确定的算法逻辑错误机械重复执行；无效输入校验失败也不等于加工服务自身暂时故障。重试不得使同一 Raw、EMA 或聚合重复计数。幂等键和提交原子性需要在详细设计中确定。

## 分类

| 分类 | 例子 | 当前处理结论 |
|---|---|---|
| 能力缺失 | 没有服务、没有字段、无法确认映射 | 记录明确原因；是否退出待 OQ-05 |
| 权限不足 | 建立接口被拒绝 | 不假定重启有效；权限提示及退出行为待定 |
| 暂时性失败 | 短暂离线、SQLite 锁竞争 | 按对应次数重试 |
| 结构性失败 | 数据损坏、schema 不兼容、关键初始化失败 | v0.3 基线为直接 Fatal |
| 重试耗尽 | 暂时性失败持续存在 | 按已确定的关键性策略升级 Fatal |

对“全部构件”与“关键构件”的范围差异必须在 OQ-05 中闭合。暂时不把任何字段缺失直接编码成应用必然退出。

## 错误码表 v1

沿用 v0.3 的 `<DOMAIN>-<TYPE>-<NNN>`。编号在整个域内未必连续；现有代码不为美观而重新编号。表中“恢复尝试”描述错误形成前的处理，不表示“重试耗尽”之后重新启动另一轮无限重试。

| 错误码 | 语义 | 恢复尝试 |
|---|---|---|
| `APP-INIT-001` | 应用初始化失败 | 结构性错误直接报告 |
| `APP-PLATFORM-002` | 运行平台不满足要求 | 不重试 |
| `SENSOR-DISCOVER-001` | 必需传感器发现失败 | 必需性待 OQ-05 |
| `SENSOR-READ-002` | 传感器读取重试耗尽 | 耗尽前执行 Sensor 重试 |
| `SENSOR-VALUE-003` | 连续取得无效传感器值 | 耗尽前执行 Sensor 重试 |
| `SENSOR-TAG-004` | 传感器标签建立失败 | 映射规则与严重性待定 |
| `DB-OPEN-001` | SQLite 打开失败 | 仅暂时性原因重试 |
| `DB-INIT-002` | SQLite 初始化失败 | 结构性错误直接报告 |
| `DB-WRITE-003` | SQLite 写入重试耗尽 | 耗尽前执行 DB 重试 |
| `DB-READ-004` | SQLite 读取重试耗尽 | 耗尽前执行 DB 重试 |
| `DB-CLEAN-005` | 数据清理失败 | 暂时性原因重试 |
| `DB-CORRUPT-006` | 数据完整性检查确认损坏 | 不机械重试 |
| `DB-SCHEMA-007` | 数据库结构与当前应用不兼容 | 不机械重试 |
| `PROC-VALIDATE-001` | 校验构件自身异常 | 不与正常拒绝无效值混同 |
| `PROC-EMA-002` | EMA 加工失败 | 仅暂时性执行原因重试 |
| `PROC-AGG-003` | 时间聚合失败 | 仅暂时性执行原因重试 |
| `PROC-TREND-004` | 趋势计算失败 | 仅暂时性执行原因重试 |
| `UI-DATA-001` | UI 数据读取重试耗尽 | 耗尽前显示已标记的缓存 |
| `UI-RENDER-002` | 关键 UI 渲染失败 | 检测方式与可恢复性待设计 |

旧示例 `SENSOR_READ_FAILED` 等不再是当前编码表。缺失能力、权限不足、超时是否新增错误码，待 OQ-05/OQ-09，不复用已有编号改变语义。

## Fatal 流程

停止接收新工作 → 记录独立日志 → 生成错误报告 → 显示错误码及重启应用指示 → 结束当前运行。

“显示完成”的判定、是否等用户确认、对话框关闭方式、最大收尾时限，以及报告写入本身失败时的兜底尚未明确，见 OQ-11。不能在界面还未可见时立即退出，也不能因报告失败而永远无法退出。

异常崩溃／强制终止无法保证走完上述流程；下次启动的残留清理和系统诊断证据属于运维设计。

## 报告字段

基本字段：`error_code`、`severity`、`timestamp`、`component`、`operation`、`retry_count`、`sensor_id`（适用时）、`application_version`、`macOS_version`、`hardware_model`、`underlying_error`。

建议补充会话 ID、系统 build、接口来源和映射版本。错误日志独立于监控数据库，保留与轮转要求见 [运维](13-operations-distribution.md)。
