# 原生界面与开源复用基线

更新日期：2026-09-18。来源：C01既有界面需求、C09开源前端复用、C10完整交接与C11实时内存路径。**开源复用方向已确认；下述布局与交互为授权细化的设计基线，尚未实现为App。**

## 1. 选定参考与复用范围

以MacMonitor的紧凑分组面板为布局基础，以Stats的分组传感器列表及菜单栏组织为交互参考，以SwiftTempBar的等宽数字和无数据占位为小组件参考。保留本项目的原生主窗口、摄氏一位小数、EMA展示与会话内72小时历史要求。

| 来源与固定实现入口 | 复用内容 | 本项目适配 |
|---|---|---|
| [MacMonitor PopoverView，2fff1062](https://github.com/ryyansafar/MacMonitor/blob/2fff106238e17e318f1b48775034c461f6464257/Macmonitor/PopoverView.swift) | `SectionBox`、标签/数值行、分隔线、滚动分组、设置入口 | 只保留CPU温度、SSD、电池；温度列表代替综合硬件仪表盘 |
| [MacMonitor AppDelegate，同版本](https://github.com/ryyansafar/MacMonitor/blob/2fff106238e17e318f1b48775034c461f6464257/Macmonitor/AppDelegate.swift) | `NSStatusItem`＋`NSPopover`＋`NSHostingController`，340×640 pt初始面板，左右键分工 | 把硬件调用移出UI；屏幕空间不足时限高滚动；复用关闭与锚点行为 |
| [Stats Sensors Popup，e31d279b](https://github.com/exelban/stats/blob/e31d279b3f27aacb19b512b26eb5ab92e166c289/Modules/Sensors/popup.swift) | 按传感器类型/组列出名称与数值、管理可见来源 | 行身份使用本项目sourceID，清理风扇写入、帮助程序与其他模块依赖 |
| [Stats Widget，同版本](https://github.com/exelban/stats/blob/e31d279b3f27aacb19b512b26eb5ab92e166c289/Kit/module/widget.swift) | 菜单栏元素生命周期、打开对应面板 | 仅一个温度入口，无需完整多模块设置框架 |
| [SwiftTempBar StatusBarController，da4b0b54](https://github.com/WHYBBE/SwiftTempBar/blob/da4b0b54e4e3d56941c3cd902b0bc877349ff190/Sources/StatusBarController.swift) | 等宽数字、无数值占位、减少无效重绘 | 保留一位小数与°C；后台采集；不复制整数显示、主线程硬件读取、温度阈值配色或自启动 |

已检查MacMonitor仓库中的[面板截图](https://github.com/ryyansafar/MacMonitor/blob/2fff106238e17e318f1b48775034c461f6464257/assets/screenshots/dashboard.png)。其中`CoreTile`显示的是**CPU占用率百分比**，不是逐核温度；本项目不引入该组件。历史图表及本项目的主窗口是本地需求扩展，不能宣称上游已经实现我们的SQLite/EMA/72小时契约。

代码与截图检查记录见[UI来源清单](research/2026-09-17-native-ui-sources.json)。三项参考固定版本均有MIT文件；实施时若复制/改写实质代码，保留作者版权、完整许可和改动记录，登记第三方声明。本轮只更新设计文档，未导入UI代码或品牌图标。

## 2. 页面与用户操作

| 界面 | 显示内容 | 操作与生命周期 |
|---|---|---|
| 菜单栏 | 温度图标＋CPU主指标EMA，格式`58.3 °C`；无值时`— °C` | 左键切换弹出面板；右键打开“打开主窗口／设置／退出”命令菜单 |
| 弹出面板 | CPU主指标、CPU温度来源、SSD、电池分组 | 再次点击图标、Esc或点击面板外关闭；底部“打开主窗口”，顶部设置入口 |
| 主窗口 | 概览数值、温度来源列表、温度柱状图、实时/历史曲线、CPU档位控件 | 关闭按钮或⌘W只关闭窗口，菜单栏及采集继续；再次打开复用当前会话 |
| 设置 | CPU五档选择、温度来源显示设置、打开日志、版本及开源许可入口 | 与主窗口档位控件共用一个状态；设置只改变后续采样 |
| 错误展示 | 错误码、原因、日志/报告位置、既有退出指示 | Fatal行为遵循06的展示30秒或用户退出、5秒收尾规则，不能因借鉴别的App而变成无限后台容错 |

退出命令或⌘Q结束整个应用，按既有会话清理要求收尾。关闭图表不停止数据采集；隐藏的图表停止绘制。菜单栏空间变化／全屏切换使锚点失效时关闭弹出面板，不因数字宽度变化频繁关闭。

主指标固定为“CPU热区最高温度”：03的12成员Raw max再EMA，详情标记开源分类证据和成员；不再使用物理Package名称。unknown来源不进入正常主指标。

## 3. 弹出面板布局

初始宽340 pt、最大高640 pt；四周内容间距16 pt，组间使用细分隔线。实际可用屏幕更小时进一步限高。标题/底部操作固定，中部内容滚动。

```text
温度监测（工作标题）                 设置
──────────────────────────────────────
CPU
  主温度（名称由定义确定）        — °C
  温度来源列表              展开/收起
    温度来源 Tp01               — °C
    温度来源 Te05               — °C
──────────────────────────────────────
SSD                             — °C
Battery                         — °C
──────────────────────────────────────
打开主窗口                       退出
```

示意中的空值不是实机数据；只有来源符合03固定profile、编码/单位证据后才显示温度，详情区别referenceClassified与targetQualified。CPU来源列表按已验证分组和显示名排序，sourceID作为稳定行身份。没有E/P域证据时不凭键名给用户显示E核/P核，更不编号为Core 0…N。

SSD主值采用已定义的SMART composite口径；NAND、邻近温度等候选放在来源详情中分列，不自动替换。电池按03的IOPS→TB1T→TB2T→TB0T优先级选择唯一来源，不平均同名服务。

## 4. 主窗口布局与图表

初始内容尺寸960×680 pt，最小800×560 pt，允许调整；这是本项目布局初值，需以实现后可读性验证调整。

```text
工具栏： CPU周期 [50 / 100 / 200 / 500 / 1000 ms]
┌──────────────────────────────────────────────┐
│ CPU主指标          SSD              Battery │
├─────────────┬────────────────────────────────┤
│ 温度来源     │ [最近5分钟][1小时][24小时][72小时]│
│ CPU         │ 温度曲线 / 峰值信息              │
│ SSD         │                                │
│ Battery     ├────────────────────────────────┤
│             │ 当前温度柱状图（按来源，单位°C）  │
└─────────────┴────────────────────────────────┘
```

- 默认选CPU主指标和最近5分钟；主指标未就绪时保持空状态，不默认替换成未知源。
- 左侧多选来源用于图表对比；名称旁明确派生指标。来源很多时滚动或筛选，不复制物理核心网格。
- 柱状图显示EMA，纵轴/横轴明确°C；同组使用同一数值尺度，超出显示范围时扩展刻度。不能把°C当作0～100%占用率，也不设未经确认的高温阈值颜色。
- 实时曲线使用EMA。较长历史用聚合avg线和min/max范围信息，悬停/选择可见时间、值、范围及样本数。历史max仅代表已记录Raw峰值。
- 空窗口、休眠和来源定义切换时断线；禁止插值跨过缺口。没有数据时显示“本会话暂无数据”，不画0°C曲线。
- 首版只提供四个“最近”范围，不提供任意过去起止区间或跨层拼接；跨度决定已有聚合层。每图最多8条来源、每条2000点，按04保留min/max降采样。

## 5. 数据来源与展示状态

| 元素 | 数据来源 |
|---|---|
| 菜单栏、实时数字、来源柱体 | 对应指标/来源EMA |
| 最近5分钟实时曲线 | EMA Ring Buffer；C11确认无需数据库往返，EMA仍按04持久化 |
| >5分钟～1小时 | SQLite的1秒聚合 |
| >1小时～24小时 | SQLite的10秒聚合 |
| >24小时～72小时 | SQLite的1分钟聚合 |
| 详情 | 注册表提供名称、来源说明、观测时间与映射状态；不让视图直接访问驱动 |

日常界面显示温度和易懂状态；原始key、provider、mappingVersion、definitionVersion、底层返回码放在可展开详情。源新鲜度未知时写“测量更新时间未知”，不能把刚完成API读取标成传感器刚刚测量。

| 状态 | 可见结果 | 数据行为 |
|---|---|---|
| 初始化/尚无有效值 | `— °C`、正在读取 | 不生成0值 |
| 有效EMA | 一位小数与°C | 同值也可能是有效读取；视图可省略无变化重绘 |
| 短暂失败，有缓存 | 缓存值＋“暂未更新”＋观测时间 | 不重新计入Raw/EMA/count |
| 超过缓存有效期 | `— °C`、数据已过期 | 观测年龄超过max(3×当前周期,2s)即过期，按06冻结 |
| 来源不支持/单位或含义未知 | 不可用＋原因 | SSD/Battery继续运行并显式不可用；CPU必需能力失败按06报告退出 |
| Fatal | 错误码与退出流程 | 不以面板占位代替既有错误报告要求 |

## 6. 视觉与可访问性基线

- 系统字体和等宽数字：正文/标签约12～13 pt，关键数值22～24 pt；采用较上游微小标签更易读的尺寸。
- 使用系统浅色/深色外观、语义文字颜色、原生材质与分隔线。半透明受“减少透明度”设置约束，不硬编码全黑背景。
- 温度系列使用固定可区分配色；颜色表示来源，不表示未经定义的健康等级。错误、过期同时有文字/符号提示，不仅依赖颜色。
- 支持键盘焦点、Esc关闭面板、系统关闭/退出快捷键；图标按钮有可访问名称；图表提供当前值及选中时间点的文本信息。
- 选择状态按sourceID保存；重连发现新实例时不得仅凭行序号把旧选择转到另一个传感器。

## 7. 实现构件与复用步骤

1. `StatusItemController`：参考两项目的NSStatusItem生命周期，只读取展示快照。
2. `TemperaturePopover`：改造MacMonitor分组/行结构；删除GPU、内存、功率、进程和helper提示等无关模块。
3. `TemperatureSourceRow`：参考Stats列表，接入本项目sourceID、EMA和质量状态；不使用上游Core标签或SMC写入。
4. `TemperatureDashboard`：复用相同Section/Row/状态组件，新增本项目的图表工作区；视图不持有SQLite连接。
5. `HistoryChartModel`：查询服务选择可用层级、输出带缺口/定义版本的图表快照，按显示点数降采样且保留min/max。
6. 移植实质代码前逐文件登记来源、MIT版权/许可和修改范围；保持业务模型与上游遥测对象解耦。

采样、存储与渲染分别调度；快照发布上限每200ms一次，隐藏窗口停止绘图。该UI节奏不改变用户CPU五档设置，性能通过W09实测验收。

## 8. UI验收清单（计划，未执行）

- 菜单栏保持摄氏一位小数；无值、缓存、过期状态不同，主线程不执行硬件读取。
- 左/右键、Esc、点击外部、全屏/锚点变化、主窗口关闭和重新打开符合第2节。
- 不存在逐物理核心温度页、Core编号网格或core_id必填；CPU热区数不要求等于物理核心数。
- CPU五档只影响后续采样；隐藏窗口不绘图但采集与会话继续。
- EMA、聚合avg/max、缺口和来源切换正确；72小时仍限本会话，不跨重启恢复。
- 检查浅/深色、减少透明度、键盘与辅助功能、小屏限高及大量来源滚动。
- 不引入上游告警、自启动、风扇控制、GPU/功耗监控、联网更新等未授权功能。
